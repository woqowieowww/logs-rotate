# logs-rotate

![Bash](https://img.shields.io/badge/Bash-4EAA25?logo=gnubash&logoColor=white)
![Platform](https://img.shields.io/badge/platform-Linux-lightgrey)

Bash-скрипт для **архивации и очистки лог-файлов** в `/var/log`: переносит логи в датированную архивную папку, настраивает права доступа и перезапускает `rsyslog`.

> [!WARNING]
> Скрипт **перемещает** все файлы верхнего уровня из `/var/log` в архив, **обнуляет** оставшиеся и перезапускает `rsyslog`. Требует root. Не запускайте его на рабочем сервере, не прочитав код и не проверив на тестовой машине.

## Что делает скрипт

1. Проверяет права root и доступность `/var/log`.
2. Создаёт архивную папку `/var/log/archive/ГГГГ-ММ-ДД_ЧЧ-ММ-СС` (права `0750`, владелец `root:adm`).
3. Переносит в неё файлы из `/var/log` (до 3 попыток на каждый файл), пропуская `archive` и `journal`.
4. Выставляет права, чтобы архив был доступен группе `adm`, в том числе из графического интерфейса.
5. Показывает число перенесённых файлов и размер архива.
6. Обнуляет оставшиеся файлы в `/var/log` и перезапускает `rsyslog`, если он активен.

## Диагностика ошибок

При ошибке скрипт останавливается и выводит код, номер строки и команду, вызвавшую сбой. Затем печатает диагностику: дату, пользователя, свободное место на диске и процессы с открытыми файлами в `/var/log`.

| Код | Причина |
|---|---|
| 1 | Нет прав root |
| 2 | Каталог логов не существует или недоступен для записи |
| 3 | Не удалось создать архивную папку |
| 4 | Не удалось переместить файл (например, заблокирован) за 3 попытки |
| 7 | Не удалось настроить доступ для GUI |
| 8 | Не удалось задать права или владельца архивной папки |

Коды 5 и 6 объявлены в скрипте, но пока не используются.

## Требования

- Linux с `systemd` и `rsyslog`
- `bash`, `find`, `lsof`, `du`, `chown`
- права root

## Установка и запуск

```bash
git clone https://github.com/woqowieowww/logs-rotate.git
cd logs-rotate
chmod +x logs_rotate.sh
sudo ./logs_rotate.sh
```

## Настройка

Параметры задаются переменными в начале скрипта:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LOG_DIR` | `/var/log` | откуда переносятся логи |
| `ARCHIVE_BASE` | `/var/log/archive` | где создаются архивные папки |
| `SERVICE_NAME` | `rsyslog` | сервис, который перезапускается после очистки |

## Автоматический запуск

Для регулярной ротации скрипт можно запускать из `cron` от root, например раз в неделю:

```cron
0 3 * * 0 /opt/logs-rotate/logs_rotate.sh >> /var/tmp/logs_rotate.out 2>&1
```

Вывод скрипта пишите **не в `/var/log`**: он переносит и обнуляет файлы именно оттуда. Сначала проверьте скрипт вручную.
